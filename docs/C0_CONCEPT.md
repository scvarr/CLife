# C0 — концептуальная модель CLife

Статус: **CURRENT / NORMATIVE**.

CLife моделирует клетку как атомарную активную сущность первого клеточного мира. Мир развивается от минимально необходимого: новые сущности и законы добавляются только когда без них нельзя выразить нужное поведение.

## Базовые принципы

- Взрослая клетка не растёт на обычном tick. Геном является чертежом готового adult phenotype; рост относится к будущим embryo/bud моделям.
- Геномные функции описывают способности объекта, а не imperative-программу.
- Конкуренция за общий runtime ресурс определяется calculator, а не порядком объявления функций.
- Мир и host взаимодействуют через числа; host интерпретирует свои каналы, но не навязывает биологические понятия.
- Физическое encoded genome, мутации и способ происхождения сложных функций пока не определены.

## Текущая универсальная онтология

`Value` — изменяемое runtime количество. `GenomeParameter` — независимый параметр функции. `CalculationDefinition` — единственный пользовательский механизм формул. `ObjectCharacteristic` — статическое свойство скомпилированного phenotype. Мир задаёт свои Units, conversions и laws.

Термины `Field`, `Resource`, `State`, `Matter`, `Measure` и `Property` не являются обязательной универсальной C++-онтологией. Они могут быть исторической терминологией или понятиями конкретного мира.

## Конструкция объекта

Готовый объект может иметь базовую конструкцию без функций. Экземпляр `FunctionType` сообщает статические требования/вклады в характеристики; одинаковые вклады сначала агрегируются. Затем отдельный world-authored `ObjectConstructionDefinition`, использующий обычную `CalculationDefinition`, вычисляет итоговые `ObjectCharacteristic`.

Например, база размера `5` и требования функций `2` не обязаны давать `7`: мир может определить `base + requirements + packaging`. Сумма является только промежуточной агрегацией вкладов функций, а не встроенным физическим законом.

Структурный материал, органика, мембрана, масса и плотность — будущие возможные входы такой construction model, но не обязательный фундамент текущей модели. Будущий embryo получает определённые миром requirements и дискретно формируется в adult phenotype; это не фиксируется как цикл по старому `MatterType` API.

## Функции и эффективность

Текущая ordinary function имеет один input, throughput, выбранный UnitConversion и несколько outputs. Buffer function имеет capacity, throughput и leakage. Это реализованный уровень, но не обещание вечного конечного набора primitives.

Независимые genome parameters через `CalculationDefinition` могут давать характеристики конкретной функции — например канал, КПД, утечку или размер. Формулы принадлежат миру, а не являются встроенным законом CLife.
